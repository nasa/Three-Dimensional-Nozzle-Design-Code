# Three-Dimensional-Nozzle-Design-Code

This package contains 3 programs written for the Microsoft Visual C++ compiler:

1) 2D Method of Characteristics, MOC_GRID_BDE
	- Computes a planar or axisymmetric two-dimensional nozzle contour based on user inputs using method of characteristics

2) Streamline Tracing Tool, STT2001
	- Performs streamline tracing on a supplied nozzle solution grid (usually generated by MOC_GRID_BDE)

3) 3D Method of Characteristics Design Tool, 3D_MOC
	- Computes three-dimensional flowfield properties for a given 3D nozzle contour. This could be a modified version of a nozzle contour generated by MOC_GRID_BDE.

Each program is contained in a separate folder containing source code and sample outputs. These programs are designed to use the Microsoft Foundation Class (MFC) libraries to generate the GUI windows for user input.

Detailed descriptions of the mathematical basis and operation of each program are provided in the attached report:

**[Rice, T., "2D and 3D Method of Characteristic Tools for Complex Nozzle Development," JHU/APL Report RTDC-TPS-481. 2003.](https://ntrs.nasa.gov/archive/nasa/casi.ntrs.nasa.gov/20030067852.pdf)**

## Quick start

1. Build the three programs (see [Building](#building)).
2. Run `compiled\MOC_Grid\MOC_Grid.exe`, enter a nozzle, and click **Calculate MOC Grid**. Choose a new, empty folder for this design when asked (for example `C:\nozzles\mach2_perfect`). Every file from every program for this design ends up in that one folder.
3. In MOC_Grid click **Run Streamline Tracing Tool** (STT2001, needs Print Option = Full) and/or **Run 3D MOC** (3D_MOC). Each opens already filled in from the run folder. Click **Execute** / **Calculate Nozzle**.
4. Look at the results: `python viewer\plt_viewer.py C:\nozzles\mach2_perfect` writes PNGs of every `.plt` file into `C:\nozzles\mach2_perfect\images`.
5. Get the nozzle into CAD: `python cad\moc_to_cad.py C:\nozzles\mach2_perfect --units mm --throat-radius 12.7` writes DXF, point and STEP files into `C:\nozzles\mach2_perfect\cad` (see [Step 5](#step-5-getting-the-nozzle-into-cad-nx)).

```
MOC_Grid  ->  run folder  ->  STT2001   (streamline tracing, friction, Isp, trimmed 3-D surface)
                          ->  3D_MOC    (3-D flowfield for a nozzle geometry)
                          ->  viewer    (PNGs in <run folder>\images)
                          ->  cad       (DXF / points / STEP for NX in <run folder>\cad)
```

## Building

Install Visual Studio with the **Desktop development with C++** workload and the **C++ MFC** component for your build tools. Open each solution, choose **Release | x64**, and build:

| Program | Solution |
|---|---|
| MOC_Grid | `MOC_Grid_BDE\MOC_Grid.slnx` |
| STT2001 | `STT2001\STT2001.slnx` |
| 3D_MOC | `3D_MOC\3DCalc.sln` |

Each build copies its program into the `compiled` folder:

```
compiled\
  MOC_Grid\   MOC_Grid.exe
  STT2001\    STT2001.exe, friction_table.txt
  3D_MOC\     3DCalc.exe, cone10.geo
```

Run the programs from `compiled`, not from the build folders. MOC_Grid starts the other two by looking for `..\STT2001\STT2001.exe` and `..\3D_MOC\3DCalc.exe` next to itself, so the three folders must stay side by side. After updating the source, rebuild all three so the buttons and the run-folder behavior below match.

## Step 1: MOC_Grid (2-D nozzle contour)

1. Run `compiled\MOC_Grid\MOC_Grid.exe`.
2. Enter the nozzle geometry, the design parameter (exit Mach, area ratio, length, or exit pressure), the flow properties and the grid settings. Set **Print Option** to **Full** if you want to use STT2001 (only a Full run writes the streamline files it needs). Set **Ideal Isp** to the real ideal Isp of your propellant, because the Cfg that STT2001 reports is divided by it.
3. Click **Calculate MOC Grid** and choose the run folder. The program saves your inputs as `MOC_Grid.inp`, calculates, and shows the nozzle plot. Close the plot; a message then confirms where everything was saved.
   - If the message says the calculation did not converge (NaN), that run cannot be used. Change the inputs and run again.
4. To repeat or change a run later, use **File > Open** on the `MOC_Grid.inp` in the run folder.

### If MOC_Grid says it could not converge on THETAB

- **Perfect nozzle fails, low expansion (for example Mach 2):** lower **DTHETAB Max (deg)** to 0.25 or 0.1. With a coarse step (1 degree, or even 0.5) the initial expansion angle of a low-Mach nozzle falls between two arc steps and the search cannot settle. Changing the downstream radius to 0.8 or 1.5 also helps.
- **RAO (Optimum Thrust) fails:** the RAO method needs the nozzle exit pressure to be clearly above the ambient pressure. If the exit pressure at your design Mach is about equal to ambient (a perfectly expanded nozzle), the optimum exit angle is about zero and there is no solution. Use the Perfect nozzle for that case, raise the design Mach, or lower the ambient pressure.
- **Set End Point:** the XEnd/R* and REnd/R* boxes are separate inputs and must agree with the flow. The area ratio is (REnd/R*)^2.
- The **THETAB Guess** only seeds the search. Use a value below half the Prandtl-Meyer angle of the exit Mach (about 10 degrees for Mach 2).

## Step 2: STT2001 (streamline tracing)

1. In MOC_Grid click **Run Streamline Tracing Tool**. STT2001 opens already pointed at the run folder, with `STT2001.inp` loaded: it names `MOC_SL.plt`, `MOC_Grid.plt`, `summary.out` and `friction_table.txt` and holds the values from this run.
2. Click **Execute**. The results are written to the same folder, named with the folder name as a prefix (for example `mach2_perfect_STT_summary.out`, `..._trimmed_P3D.dat`, `..._trimmed_P3D.xyz`, `..._all_runs.dat`). Click **Plots** to view the centerline plots.

STT2001 reads and writes every file in the run folder. Opening an `.inp` (File > Open, or from MOC_Grid) switches it to that file's folder. If you start `STT2001.exe` by hand and press **Execute** before opening an `.inp`, it asks which folder to use. You can also start it from a command prompt with the `.inp` as the argument:

```
compiled\STT2001\STT2001.exe "C:\nozzles\mach2_perfect\STT2001.inp"
```

The default setup traces the full axisymmetric MOC flowfield: the throat is one circle of radius R* = 1 in, swept 0 to 360 degrees with 72 streamlines. The throat area and the mass flow come from this run's `summary.out`, so the Isp STT2001 reports should be close to the MOC Isp. To design a different 3-D nozzle, change the streamline trimming rows in STT2001 and use **File > Save As** to keep the new setup. Any saved `.inp` can be loaded again with **File > Open**, so keep each `.inp` with its MOC files.

## Step 3: 3D_MOC (3-D flowfield)

1. In MOC_Grid click **Run 3D MOC**. It is enabled after any good run, whether the Print Option is Normal or Full.
2. 3D_MOC opens already pointed at the run folder and fills itself in from the files there:
   - the **Initial Plane Properties** come from `summary.out`: the total conditions, gamma and molecular weight, with a uniform plane whose Mach number carries the same mass flow as the MOC throat (so the plane's static pressure and temperature are consistent with the run). The run folder is shown in the **Output folder** label and in the window title;
   - the nozzle wall comes from `Summary.plt` (or `wall.out`) and is written to the folder as `<folder name>.geo` (throat radius R* = 1 in, so X/R* and R/R* are inches). Only axisymmetric MOC_Grid runs can be used;
   - the settings are saved as `3D_MOC.inp` in the same folder. The next time the folder is opened those saved settings are loaded, unless MOC_Grid has calculated again since: then they are refilled from the new results and the old geometry file is kept as `<folder name>_previous.geo`.
3. Click **Calculate Nozzle**. All output files (`Wall.plt`, `Streamlines.plt`, `full_mesh.plt`, `axialStations.plt`, `outfile.out`, and the others) are saved in the run folder, not next to `3DCalc.exe`.

Starting 3D_MOC by hand:

- Run `3DCalc.exe`, click **Open MOC_Grid Folder...** and choose the run folder; or start it from a command prompt with the folder as the argument: `compiled\3D_MOC\3DCalc.exe "C:\nozzles\mach2_perfect"`.
- If you press **Calculate Nozzle** before opening a folder, it asks for the output folder first.
- If the folder has no MOC_Grid results, you get a warning. You can still enter a geometry file and flow conditions yourself, and the output is saved in that folder.

To use your own nozzle shape, edit the `.geo` file in the run folder and click **Calculate Nozzle** again. The file is a header with the number of axial stations, a title line, then one `Z R0 X0 Y0` row per station: a circle of radius R0 centred on (X0, Y0) at axial position Z, in inches. For an axisymmetric nozzle X0 = Y0 = 0.

## What ends up in the run folder

| File | Written by | Purpose |
|---|---|---|
| `MOC_Grid.inp` | MOC_Grid | The inputs of the run. Open it later with **File > Open** in MOC_Grid. |
| `summary.out`, `Summary.plt`, `MOC_Grid.plt`, `MOC_SL.plt`, `center.out`, `wall.out`, and other `.out` / `.plt` files | MOC_Grid | The MOC solution. (`MOC_Grid.plt`, `MOC_SL.plt`, `center.out` and `wall.out` need Print Option = Full.) |
| `STT2001.inp` | MOC_Grid | Ready-to-run setup for STT2001. If the file already exists it is first renamed `STT2001_previous.inp`. |
| `friction_table.txt` | MOC_Grid (copied) | Friction table used by STT2001. Edit this copy to change the friction model for this run. |
| `<prefix>_*.out`, `.dat`, `.xyz`, `.plt` | STT2001 | The streamline tracing results. |
| `<folder name>.geo`, `3D_MOC.inp` | 3D_MOC | The nozzle geometry and the settings of the 3D run. |
| `Wall.plt`, `Streamlines.plt`, `full_mesh.plt`, `axialStations.plt`, `Initial Wall.plt`, `outfile.out`, ... | 3D_MOC | The 3-D solution. |
| `images\*.png` | viewer | Pictures of every `.plt` file. |
| `cad\*_flow.dxf`, `*_wall.dxf`, `*_profile.dat`, `*_flow.step`, ... | cad\moc_to_cad.py | The nozzle contour for CAD. |

Make a new folder for each design. Running a second design in the same folder overwrites the first one's output files.

## Step 4: Viewing the .plt files

The `.plt` files written by all three programs are Tecplot files (ASCII, or binary such as the 3D_MOC samples). `viewer\plt_viewer.py` plots them without Tecplot. It needs Python 3.9+ with numpy and matplotlib:

```
pip install -r viewer\requirements.txt
```

Point it at the run folder to get a PNG of every `.plt` file in an `images` subfolder of that folder. Run it again after STT2001 and 3D_MOC have written their files:

```
python viewer\plt_viewer.py C:\nozzles\mach2_perfect           # PNGs in C:\nozzles\mach2_perfect\images
python viewer\plt_viewer.py C:\nozzles\mach2_perfect --show    # same, and also open the windows
```

Or look at one file in a window (3-D views can be rotated with the mouse):

```
python viewer\plt_viewer.py Summary.plt                 # contour + Mach, pressure, angle along the wall
python viewer\plt_viewer.py MOC_Grid.plt --mirror       # characteristic net colored by Mach
python viewer\plt_viewer.py MOC_SL.plt --var Pres       # streamlines colored by pressure
python viewer\plt_viewer.py mach2_perfect.plt           # STT2001 trimmed nozzle surface
python viewer\plt_viewer.py Wall.plt --mode 3d --var Mach   # 3D_MOC wall surface
python viewer\plt_viewer.py full_mesh.plt               # 3D_MOC flowfield and exit plane
python viewer\plt_viewer.py Summary.plt --list          # zones and variables only
```

| Option | Meaning |
|---|---|
| `--mode grid \| summary \| streamlines \| 3d \| field \| xy` | Override the view (it is chosen from the file contents by default). |
| `--var NAME` | Variable used for the color (a prefix is enough, for example `Mach`, `Pres`). |
| `--mirror` | Also draw the lower half of the 2-D axisymmetric views. |
| `--cmap NAME`, `--elev`, `--azim` | Colormap and 3-D camera angle. |
| `--save PATH` | Save PNGs to this file or folder instead of `images`. |
| `--show` / `--no-show` | Open windows for a folder / never open windows. |

Binary files are supported for structured zones (Tecplot binary versions 7.5 and 10.8-11.2); finite-element zones in them are skipped with a note. `python -m pytest viewer` runs a smoke test over every sample `.plt` in the repository.

## Step 5: Getting the nozzle into CAD (NX)

MOC_Grid, STT2001 and 3D_MOC write only analysis files (`.plt`, `.out`, `.xyz`, `.geo`), and the contour in them is nondimensional (X/R*, R/R*). None of them is a CAD format, so `cad\moc_to_cad.py` converts the nozzle contour of a run into files NX can import and revolve. It scales the contour to your real throat radius, and writes everything to `<run folder>\cad`.

```
pip install -r cad\requirements.txt
python cad\moc_to_cad.py C:\nozzles\mach2_perfect --units mm --throat-radius 12.7
```

Choose the size with one of these (without either, the contour keeps the 1 in throat radius that MOC_Grid ran):

- `--throat-radius R` : the throat radius, in the units you chose with `--units in|mm|cm|m`.
- `--mass-flow LBM_S` : size the throat so the nozzle passes this mass flow in lbm/s. MOC_Grid's 2-D mass flow in `summary.out` is for a 1 in throat and scales with the radius squared, so R* = 1 in x sqrt(mass flow / that value).

| File | What it is | How to use it in NX |
|---|---|---|
| `<name>_flow.dxf` | Closed half-section of the **flow path**: one cubic spline for the wall, plus the inlet line, the axis and the exit line. | **File > Import > AutoCAD DXF/DWG**, then **Insert > Design Feature > Revolve**. Select the curves as the section and the axis line as the axis, 0 to 360 degrees. The result is the gas volume (for a CFD domain, or to subtract from a block). |
| `<name>_wall.dxf` | Closed half-section of the **nozzle wall** (inner and outer spline, flat caps). Only written with `--thickness T`. | Same as above. The result is the wall solid. |
| `<name>_profile.dat` | The wall points as `x y z` lines (units as chosen). | **Insert > Curve > Spline > Through Points > Points from File** gives the wall curve; revolve it to get a surface. |
| `<name>_profile.csv` | The same points with a header. | Spreadsheets and other CAD tools. |
| `<name>_flow.step`, `<name>_wall.step` | The same sections already revolved into solids. **Always in millimetres**, whatever `--units` is. | **File > Import > STEP**. This is a dumb (non-parametric) solid. Use the DXF route when you want a sketch you can edit. Needs `cadquery`; `--no-step` skips it. |

Other options:

- `--thickness T` : adds the wall files. T is measured normal to the flow surface, and the inlet and exit are cut flat, perpendicular to the axis.
- `--axial x|z` : the nozzle axis along X with the profile in the XY plane (default), or along Z with the profile in the XZ plane. Revolve about that axis.
- `--min-spacing F` : MOC_Grid puts many points close together at the throat. Points closer than F x throat radius to the last kept one are dropped before fitting (default 0.002; use 0 to keep every point). The script prints the largest distance between the original points and the fitted spline (typically a few thousandths of a unit).
- `--out DIR`, `--name NAME` : where to write and the file name prefix (default: the run folder's `cad` subfolder and the run folder's name).
- The input can also be a `Summary.plt` or `wall.out` file, or a 3D_MOC `.geo` file (for example one you edited), as long as X0 and Y0 are zero.

What you get is the **throat-to-exit contour** that MOC_Grid designs. It has no converging inlet section, chamber, flange or wall features; add those in NX. The throat plane is at axial position 0. The script prints the throat and exit radii, the length, the area ratio and the volumes, so you can check them against the MOC_Grid `summary.out` (the area ratio should match).

This covers axisymmetric nozzles, which is what a revolve produces. The non-axisymmetric surfaces that STT2001 can trim (`*_trimmed_P3D.xyz`, a PLOT3D point grid) are not converted by this script.

I tested the DXF files by reading them back (one cubic spline plus lines that form a closed loop, with the spline passing through the contour points) and the STEP files by re-importing them (valid single solids whose volume matches the integral of the contour), but not inside NX itself. After the first import, check the units and the size of the part (throat diameter, length) against what you asked for. Menu names can differ slightly between NX versions. If the DXF import dialog offers a scale option, leave it at 1.

## Sample results

The `outputs_*` folders hold the original authors' sample results, which are useful to compare against your own results. They are not read by the programs.
